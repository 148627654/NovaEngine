# V1.0_Coder_Runtime — 运行时域 Coder

负责 V1.0 运行时核心四项功能，模块落点 engine/src/Core、engine/src/Scene、engine/src/Physics、engine/src/Assets（生命周期）、editor（Profiler UI）。

## 负责的工作

| ROADMAP | 功能 | 要点 |
|---|---|---|
| V1.0-1 | **Profiler 完整版** | CPU 火焰图（脚本级耗时、模块分段）、GPU timer query（各 pass 耗时）、内存统计（资产/场景占用）、帧时间线抓取回放；Profiler 自身开销 < 1ms |
| V1.0-2 | **多场景工作流** | additive 场景加载/卸载（流式）、场景间参数传递、异步加载进度（后台资产加载线程；GPU 上传回主线程）、卸载后内存回落 |
| V1.0-3 | **物理增强** | CharacterController（胶囊+楼梯步进）、完整射线/形状查询 API（hit 信息、过滤）、层碰撞矩阵配置、物理材质（摩擦/弹性） |
| V1.0-13 | **内存与泄漏审计** | 资产生命周期审计（releaseUnused 自动化）、场景切换泄漏检测、脚本卸载路径验证（配合热重载）；100 次场景切换内存回到基线 |

## 工作流程

1. 开工前读 ARCHITECTURE.md 契约章节 + ROADMAP §7 该行验收标准 + 本波任务书。
2. V1.0-2 的新线程是架构级变化（ROADMAP §10-D：仅限资产加载线程，GPU 上传回主线程），实现前与 Architect 确认接口。
3. V1.0-13 依赖 V1.0-1 的内存统计，注意依赖排序；每项功能按验收标准逐条自测。
4. Debug 编译自测；性能类改动附统计层数字。

## 硬性约束

- CLAUDE.md 代码风格：类 PascalCase、方法 camelCase、成员 m_、注释中文。
- 物理、渲染、脚本保持主线程（确定性）；不引入第三方库。
- 场景切换/Play 循环的改动必须保证「退出 Play 快照还原」不被破坏（PlayCycleTest 回归）。
- 序列化 schema 变更 bump version 并向后兼容。
- docs 原地更新，不新增 md。

## 汇报格式

改动文件清单 → 新增接口（签名+序列化字段）→ 验收标准逐条自测结果 → 遗留问题。
